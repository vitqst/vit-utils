# All Tools Implementation Plan

**Goal:** Implement every tool advertised by the 41-entry catalog as a useful,
bilingual, accessible, lazy-loaded browser tool, with user data kept local except
for an explicitly reviewed HIBP k-anonymity request.

**Current evidence:** The catalog advertises 41 tools. Only `photo-cure` has a
runnable registry entry and product specification. The baseline suite passes 24
tests across three files.

## Architecture and scope

- Treat the 41 entries in `src/registry/group-catalog.ts` as the delivery scope.
- Make `src/registry/tool-catalog.ts` the only metadata source. Derive groups,
  navigation, search, static pages, the sitemap, and runtime loaders from it.
- Keep one lazy entry module under `src/tools/<id>/` per tool.
- Share accessible workspace controls and pure domain helpers where jobs overlap;
  do not collapse distinct tools into one generic runtime.
- Give each tool a focused product specification before implementing it.
- Pass the active locale into tool modules so English and Vietnamese copy ship
  together.
- Use workers for large files, PDF/image transforms, archives, spreadsheets, and
  file hashing. Every worker operation must be cancellable.
- Keep inputs and derived data in memory or browser storage. The HIBP tool is the
  sole planned network exception and requires its own privacy/security review
  before implementation.

## Test-first workflow for every item

1. Add or update its product specification.
2. Write the smallest behavior test for one user-visible capability.
3. Run the focused test and confirm the expected failure.
4. Implement only enough behavior to pass.
5. Re-run the focused test and relevant registry/shell tests.
6. Repeat for validation, empty/error states, keyboard use, and locale behavior.
7. Run the group's tests before starting the next group.

## Verification gates

- `npm test`
- `npm run typecheck`
- `npm run build`
- `npm run check`
- Inspect `dist/` for a static route and separate lazy chunk for all 41 tools.
- Browser-test every tool's primary flow and error state in English and Vietnamese.
- Check keyboard navigation at desktop and mobile widths.
- Confirm no tool performs an outbound request except the disclosed HIBP prefix
  lookup.
- Confirm worker-backed operations can be cancelled and do not leave object URLs,
  workers, or large buffers alive after reset/unmount.

## Completion rule

Move this file to `docs/exec-plans/completed/` only when every checkbox is
verified by current test, build, and browser evidence. Passing registry tests alone
does not count as implementing a tool.
